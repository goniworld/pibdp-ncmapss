# PI-BDP × N-CMAPSS 프로토콜 추가본 v1.1 — 문헌 모델 비교 (탐색 분석)

- 작성일: 2026-10-28. **이 문서를 커밋한 시각이 이 추가본의 고정 시각이다.** 아래 분석은 이 커밋 이후에만 실행한다.
- 기준 문서: 프로토콜 v1.0 (고정 커밋 `d2ecc6e`, 2026-10-21)
- 함께 커밋하는 파일: 이 문서, `공개코드_조사표.md`, `E0_문헌조사.md`
- 노트북은 별도 커밋으로 추가한다. 노트북 커밋도 첫 실행 전에 한다. 그 커밋 주소를 실행 기록에 남긴다.

## 0. 위치와 원칙

1. **v1.0의 확증 결과는 그대로 둔다.** 이 추가본은 v1.0의 가설, 지표, 결과를 바꾸지 않는다. v1.0의 비교 모델(RF, GB, MLP, LSTM, CNN, RawCNN)은 원고에서 "같은 정보를 받는 일반 모델 기준선(information-matched baselines)"으로 부른다.
2. **이 추가본의 분석은 모두 탐색 분석이다.** v1.0 test 결과를 본 뒤에 설계했기 때문이다. 원고에서는 5.6절에 탐색 분석으로 보고한다. p값은 사전 등록 가설의 검정으로 쓰지 않는다.
3. **연구자 자유도를 미리 없앤다.**
   - 비교 대상은 2절의 규칙으로 정한 목록으로 고정한다.
   - 비교 모델의 설정은 공개 코드와 원 논문의 값을 그대로 쓴다.
   - test 데이터로 조정하거나 고르는 것은 아무것도 없다.
   - 실행한 모든 모델, 시드, 지표를 보고한다. 결과를 보고 빼는 것은 없다.
4. **PI-BDP는 다시 학습하지 않는다.** v1.0 Phase 3에서 고정된 test 예측(`test_PI-BDP_V0_*.csv.gz`)과 고정된 보정 상수 c_α를 그대로 쓴다.
5. 이 문서와 다르게 실행한 것은 모두 "추가본 이탈"로 표시해 보고한다.

- E2a의 CruiseBench 수치는 각 실행에서 시험 RMSE가 가장 좋은 epoch을 고른 값이라 낙관적이다. 이 점을 표 설명에 적는다.
- E2c는 마지막 epoch을 쓰므로 그 편향이 없다.
- E2b는 figshare 파일의 내용과 이용 조건을 확인한 뒤에 진행한다. 이용할 수 없으면 하지 않고, 그 사실을 보고한다.

## 2. E2c 비교 대상 (공개 코드 실행)

### 2.1 선정 규칙
다음을 모두 만족하는 N-CMAPSS RUL 연구의 모델을 비교 대상으로 한다.
1. 게재처가 SCIE 저널 또는 국제학회이다. 예외로 CruiseBench(arXiv)를 지도교수 승인으로 포함한다.
2. 저자가 공개한 공식 코드가 2026-10-28 현재 있다.
3. 코드가 N-CMAPSS 원자료(HDF5)와 공식 dev/test 분할로 바로 실행된다.

조사 결과(`공개코드_조사표.md`) 이 규칙을 만족하는 것은 두 저장소이다.

### 2.2 대상 목록 (고정)

| 저장소 (커밋) | 포함 모델 | 제외 모델과 이유 |
|---|---|---|
| CruiseBench `ef26d40` | LSTM, GRU, TCN, TSMixer | 없음 |
| bayesrul `2943f4d` (Basora et al., RESS 2025) | HNN, MCD, DE | 베이지안 신경망 LRT, FO, RAD. TyXe·pyro의 오래된 버전에 묶여 있어 Colab 설치가 불확실하다. 원 논문 초록은 어느 방법도 모든 면에서 분명히 앞서지 않았고, HNN이 베이지안 신경망의 추가 복잡도 없이 좋은 성능을 냈다고 보고했다. 이 제외는 실행 전에 정했다. |

### 2.3 공개 코드 사용 방식
두 저장소 모두 라이선스 파일이 없다. 따라서 다음과 같이 쓴다.
- 공개된 코드를 연구 목적으로 실행하고, 그 결과(수치)를 보고한다. 원 논문과 저장소를 인용한다.
- 원 코드를 복사해 재배포하지 않는다. 바꾼 부분(diff)과 실행 방법만 공개한다.
- 저자에게 사용 사실을 알리는 메일은 예의로 보낼 수 있으나, 실행 조건은 아니다. 저자가 사용 중단을 요청하면 그 저장소의 결과를 빼고, 그 사실을 보고한다.

## 3. E2c 실행 설정

### 3.1 공통
- 데이터: 9개 서브셋(DS01-005, DS02-006, DS03-012, DS04, DS05, DS06, DS07, DS08a-009, DS08c-008)과 공식 dev/test 분할. DS08d는 v1.0과 같은 이유로 뺀다.
- 코드 수정은 다음만 허용한다.
  - 데이터 경로
  - 서브셋 목록
  - 장치 설정
  - test 예측을 창 단위로 저장하는 출력 코드: 서브셋, 엔진, 사이클, 창 번호, 상한 RUL, 상한 없는 RUL, 예측값(평균·분산 등)
  - 시드 값 지정
  - CruiseBench의 매 epoch test 평가를 끄고, 마지막 epoch 뒤에 한 번만 평가하는 것. 학습에는 영향이 없고, 학습 도중 test 성능을 보지 않기 위해서이다.
- 모델, 손실, 최적화, 전처리, 레이블, 학습 일정은 바꾸지 않는다. 바꾼 코드는 diff로 남긴다.
- dev 엔진 사용은 각 코드의 원래 방식을 따른다. 고장 전에 관측이 끝난 dev 엔진 5대를 빼지 않는 것도 그대로 둔다.

### 3.2 CruiseBench
- 원 논문 기본 설정 `CruiseBench-eta5-W256-S10`을 따른다. 순항 구간 마스크(공개 파일)를 쓰고, 창 256, 간격 10, η = 5% 상한(서브셋별 38, 34, 34, 43, 38, 41, 39, 34, 28)이다. Adam 3e-4, 스케줄러 없음, 50 epoch, 배치 512이다. 서브셋마다 모델을 따로 학습한다.
- **시드는 5회(원 논문과 같음)이다.** 원 코드는 시드를 무작위로 뽑으므로(`--seed -1`), 재현을 위해 1–5로 지정한다.
- 평가에는 50번째 epoch이 끝난 모델을 쓴다. 중간 epoch의 모델을 고르지 않는다.
- 계산량 예외 규칙: 첫 실행(DS01, LSTM)의 첫 epoch 학습 시간만 재서, 180회 전체 예상 시간이 GPU 40시간을 넘으면 **모든 모델의 시드를 3회로 줄인다.** 이 판단에는 학습 시간만 쓰고, 어떤 성능 지표도 보지 않는다. 줄였다면 추가본 이탈로 보고한다.

### 3.3 bayesrul
- 저장소의 실험 설정 `ncmapss_hnn`, `ncmapss_mcd`와 학습 스크립트(`scripts/train_hnn.sh`, `scripts/train_mcd.sh`)의 실행 옵션을 그대로 쓴다. 학습률, weight decay, dropout, MCD의 MC 표본 20(스크립트 값), 최대 500 epoch, patience 50 조기종료, dev의 10% 무작위 검증 분할이 포함된다.
- 데이터 설정은 원 논문 값을 따른다. 입력 W + X_s, 0.1 Hz(skip 10), 창 30, 간격 10, 건전 구간 상한 RUL이다. 서브셋 목록만 9개로 바꾼다. 원 논문처럼 모든 서브셋을 묶어 모델 하나를 학습한다.
- HNN은 시드 1–10으로 10회, MCD는 시드 1–5로 5회 학습한다.
- DE는 저장소의 방식(`conf/metrics.yaml`: HNN 5개씩 묶은 앙상블 5개, `random.seed(1)`로 조합 선택)대로 HNN 10회 결과에서 만든다. 추가 학습은 없다.

### 3.4 재현 확인 단계 (E2c의 첫 단계)
- 우리가 공개 코드를 제대로 돌리는지 확인하기 위해, 9개 서브셋 본 실행 전에 원 논문의 조건을 그대로 재현한다.
  - CruiseBench: DS01과 DS04에서 LSTM과 TSMixer를 시드 1–5로 실행하고, **원 논문 방식대로 최고 epoch 값**을 계산해 표 6.1과 비교한다.
  - bayesrul: 원 설정(DS01–DS05 묶음)으로 HNN을 실행해 원 논문 표와 비교한다.
- **판정 기준:** 우리 평균이 원 논문 평균 ± (원 논문 표준편차의 2배, 최소 0.3 사이클) 안에 들면 "재현됨"으로 본다.
- 재현되지 않으면 원인(환경, 버전, 데이터 경로 등)을 찾아 고친 뒤 한 번 더 시도한다. 그래도 안 되면 그 저장소의 E2c 결과는 "재현되지 않은 실행"으로 표시해 보고한다.
- 재현 확인에 쓴 최고 epoch 값은 재현 판정에만 쓴다. PI-BDP와의 비교에는 4.1절의 마지막 epoch 값을 쓴다.

## 4. 채점

### 4.1 원래 방식 (주 채점)
E2a·E2b·E2c 모두 각 코드의 레이블과 창으로 채점한다. E2c의 CruiseBench 모델은 50번째 epoch 모델로 채점한다. CruiseBench는 η = 5% 상한 레이블과 순항 창, bayesrul은 건전 구간 상한 레이블과 0.1 Hz 창이다. 지표는 서브셋별 값, 통합 값, 서브셋 평균을 보고한다.

### 4.2 PI-BDP를 같은 창에 놓는 규칙
- **정보 시점:** 사이클 t의 창에는 사이클 t − 1이 끝난 뒤의 PI-BDP 출력에서 1을 뺀 값을 쓴다. 비행 도중의 창에 그 비행이 끝나야 알 수 있는 정보가 들어가지 않게 하기 위해서이다. 분위수에도 같은 이동을 적용한다.
- 각 엔진의 첫 사이클 창은 **모든 모델에서** 채점에서 뺀다.
- **상한:** 그 방식의 레이블 상한을 PI-BDP와 비교 모델의 모든 예측값·분위수에 똑같이 적용한다(min(값, 상한)).
- **PI-BDP 점 예측**은 중앙값(q500)이다.
- **PI-BDP 예측구간**
  - 보정한 90% 구간: 원고 식 (12), 고정된 c_α
  - 보정하지 않은 구간: 저장된 분위수
- **E2a:** 비교 모델 쪽은 논문 표 6.1의 수치를 그대로 쓴다. PI-BDP만 이 규칙으로 같은 창에서 채점한다. 예측값이 없으므로 6절의 검정은 하지 않는다.
- **비교 모델 점 예측 (E2b·E2c)**
  - CruiseBench: 시드 평균
  - HNN·MCD: 예측 분포 평균의 시드 평균
  - DE: 앙상블 5개 각각의 평균을 다시 평균

### 4.3 사이클 단위 방식 (보조 채점)
v1.0과 같이 상한 없는 사이클 단위로 채점한다. 비교 모델은 한 사이클 안의 창 예측을 평균해 사이클 예측으로 쓴다. 상한 레이블로 학습한 모델에 불리한 방식이므로 보조 결과로만 보고하고, 그 점을 함께 적는다.

## 5. 지표

- **점 예측:** RMSE(통합, 서브셋 평균, 서브셋별)
- **확률 예측:** 확률 출력이 있는 모델(PI-BDP, HNN, MCD, DE)만 계산한다.
  - 90% 포함률, 평균 폭, interval score (α = 0.1)
  - 분위수 평균 CRPS 근사: 분위수 수준 {0.025, 0.05, 0.1, 0.25, 0.5, 0.75, 0.9, 0.95, 0.975}의 pinball loss 평균. 가우시안 출력은 같은 분위수를 계산해 쓴다.
  - bayesrul 고유 지표(NLL, RMSCE, sharpness)는 원래 방식으로 함께 보고한다.

## 6. 통계

- E2b·E2c에서 PI-BDP V0와 각 비교 모델의 차이를 v1.0과 같은 계층 붓스트랩(서브셋 → 엔진 재표집, 100,000회)으로 구한다. 대상은 통합 RMSE와 interval score이다.
- 95% 신뢰구간과 보정하지 않은 p값을 보고한다. 탐색 분석이므로 "유의하게 확인되었다"는 표현은 쓰지 않는다.

## 7. E1 — DS02 문헌 표

- **포함 규칙:** 1–2번 인용 기준을 만족하고, DS02 표준 분할(학습 2, 5, 10, 16, 18, 20 / 시험 11, 14, 15)에서 시험 RMSE를 보고한 연구.
- 값은 원문 PDF의 표·쪽을 확인해 옮긴다. 채점 단위(표본/창/사이클), 표본화 빈도, 상한 여부를 열로 함께 적는다.
- PI-BDP 줄은 고정된 test 예측으로 계산한다. 채점 단위가 같은 줄끼리만 비교하고, 단위가 다르면 표에 그렇게 표시한다.
- 새 학습은 하지 않는다.

## 8. A1·A2 — 기존 예측값 추가 분석

- **A1:** RUL 최대치 100으로 상한을 둔 예측(v1.0의 Clipped RMSE)으로 v1.0과 같은 계층 붓스트랩 검정을 한다. 비교 대상은 v1.0의 다섯 비교 모델이다. 보정하지 않은 p값과 Holm 보정 p값을 둘 다 보고한다.
- **A2:**
  - 보정한 90% 구간의 서브셋별·엔진별 포함률. 최악의 엔진 포함률도 보고한다.
  - LB90 한쪽 보정: 실제 RUL이 LB90보다 작은 사이클의 비율. 기대값은 5%이다.
  - 이 비율을 서브셋별로, 그리고 수명 구간별(0–25, 25–50, 50–75, 75–100%)로 보고한다.

## 9. 결과 보고 원칙 (결과를 보기 전에 정함)

1. E2a·E2b·E2c의 모든 모델과 시드를 표에 싣는다. 본문 표에는 모델별 시드 평균을, 부록에는 전체를 싣는다.
2. E2b·E2c의 표현은 6절 붓스트랩의 95% 신뢰구간에 따라 정한다. E2a는 검정 없이 수치만 나란히 놓고, "보고된 값보다 높다/낮다"로만 쓴다. 점 예측(RMSE)과 예측구간(interval score)에 따로 적용한다.
   - 비교 모델 쪽으로 0을 벗어남 → "PI-BDP는 X보다 덜 정확했다(less accurate than X)"
   - 0을 포함함 → "비슷했다(comparable)"
   - PI-BDP 쪽으로 0을 벗어남 → "이 탐색 비교에서 X보다 정확했다"
3. 초록과 하이라이트에는 E2에서 가장 정확한 비교 모델과 PI-BDP의 관계를 2의 표현대로 반드시 넣는다. E2a와 E2c의 결론이 다르면 둘 다 적는다.
4. v1.0의 확증 결과는 "같은 정보를 받는 일반 모델 기준선보다 낮은 RMSE"로만 표현한다.
5. 결과가 PI-BDP에 불리하면, 정확도 우위 주장을 빼고 기여를 다음으로 서술한다.
   - 해석 가능성 (실제 손상과의 일치)
   - 보정된 예측구간
   - 적은 고장 자료에서의 동작
   - 사전 등록된 평가 절차
