## 1. M1 — 비용률 최소화 정비 규칙 (예측분포 전체 사용)

### 1.1 질문

사후 정비 시뮬레이션(원고 5.6.2절)의 PI-BDP 규칙은 비용비 ρ와 관계없이 보정된 5% 분위수(LB90)를 임계값 τ = 6과 비교했다. 예측분포 전체와 비용비 ρ를 함께 쓰는 의사결정 규칙은 임계값을 따로 조정하지 않고도 다운타임을 줄이는가? 이 규칙은 분포가 있어야 만들 수 있으므로 점예측 모델에는 해당하지 않는다.

### 1.2 규칙 (ER, expected-rate replacement)

- **대상:** 시험 엔진의 매 사이클 t와 그 사이클의 V0 예측분포
- **분위수 9개(2.5, 5, 10, 25, 50, 75, 90, 95, 97.5%)**
  - 주 분석(ER-cal): 사전 고정 보정 상수(50/80/90/95% 수준별 c)로 각 수준의 구간을 중앙값 기준으로 넓힌다. 하한은 0에서 자르고 최소 반폭 ε = 0.5를 쓴다(원고 식 (12)와 같음). 그다음 누적 최댓값으로 단조 증가하게 맞춘다.
  - 보조 분석(ER-raw): 보정 전 분위수
- **누적분포 F(r) = P(RUL ≤ r):** 분위수 점들을 잇는 구간 선형 함수
  - 같은 값을 가진 분위수는 가장 큰 수준만 남긴다.
  - 아래 꼬리: 2.5–5% 구간의 밀도로 직선을 연장해 0이 되는 곳까지 잇는다. 그 점이 0보다 작으면 0 아래 몫은 RUL = 0의 질량으로 둔다.
  - 위 꼬리: 95–97.5% 구간의 밀도로 1이 될 때까지 잇는다.
- **장기 다운타임률:** 지금부터 r 사이클 뒤 교체를 계획할 때

  g(r) = D_p [ (1 − F(r)) + ρ F(r) ] / ( t + Σ_{s=0}^{r−1} (1 − F(s)) ),  r ∈ {L, L+1, …, R}

  - L = 5 (리드타임), D_p = 2, R = 위 꼬리 끝(올림), R < L이면 R = L
  - 분자는 계획정비(D_p)와 고장(ρD_p)의 기대 다운타임, 분모는 이 엔진이 교체될 때까지의 기대 운용 사이클
- **판단:** g가 r = L에서 최소이면(동률이면 가장 이른 r) 그 사이클에 정비를 발령한다.
- **시뮬레이터:** 사후 정비 노트북과 같다. Δt = 1, 첫 발령 시점 t에서 t + L < EOL이면 계획정비(사용 수명 t + L), 아니면 EOL에서 비계획 고장.
- **근거:** 잔여수명분포로 기대 비용률을 최소화하는 센서 기반 교체(Elwany & Gebraeel, 2008)와 연령 교체(Barlow & Hunter, 1960)를 엔진별 사후 예측분포에 적용한 것이다.

### 1.3 비교와 지표

- ρ ∈ {2, 5, 10, 20, 50}마다 1,000 사이클당 다운타임, 비계획 고장률, 평균 미사용 수명(기술 통계)
- **주 비교 (ρ = 10):** 사후 노트북과 같은 계층 붓스트랩(서브셋 → 엔진, 20,000회, 시드 1)으로 다음 차이의 95% 구간을 낸다.
  - (a) ER-cal − LB90 (조정 없음, τ = 6)
  - (b) ER-cal − TBM (Weibull 최적 연령)
  - (c) ER-cal − 조정 GB (개발 예측에서 고른 τ; 사후 결과에서 ρ = 10일 때 가장 낮았던 조정 점예측 모델)
  - 보조: ER-raw − LB90
- **재현 점검(실행 조건):** 같은 코드로 다시 계산한 LB90, TBM, 조정 GB의 ρ = 10 다운타임이 사후 결과(51.928, 41.981, 47.599)와 0.01 이내로 같아야 한다. 다르면 멈추고 원인을 기록한다. LB90의 붓스트랩 95% 구간(사후 결과 29.526–85.890)도 함께 출력해 붓스트랩 표본이 같은지 확인한다(실행 조건은 아님).
- 서브셋별 결과(ρ = 10)는 기술 통계로만 낸다.

### 1.4 표현 규칙

- 차이의 95% 구간이 0보다 작으면 "더 낮은 다운타임", 0보다 크면 "더 높은 다운타임", 0을 포함하면 "유의한 차이 없음"으로 쓴다.
- 탐색 분석이므로 다중성 보정은 하지 않고, 결과 옆에 탐색 분석임을 적는다.

## 2. M2 — 계산 비용

### 2.1 질문

PI-BDP와 비교 모델을 학습하고 예측하는 데 드는 계산량은 어느 정도인가?

### 2.2 측정

- Colab CPU 런타임(GPU 없음). CPU 모델, 코어 수, Python·numpy·scipy·scikit-learn 판을 기록한다.
- **PI-BDP V0:** 동결 라이브러리(SHA-256 `468de08c…`)와 `config.json` 설정
  - 서브셋마다 (i) 개발 엔진 전체로 적합 3회, 중앙값 시간 (ii) 시험 자료의 Δz 계산 시간(재적합 없음) (iii) 시험 엔진 모든 사이클 예측 1회(몬테카를로 표본 4,000개, Phase 3과 같음), 사이클당 평균 시간
  - 재현 점검: 다시 계산한 q500, q050과 저장된 Phase 3 예측의 최대 절대 차이를 기록한다. 라이브러리 판 차이로 작은 차이가 날 수 있으며, 시간 측정에만 쓰고 결과 수치는 바꾸지 않는다.
- **RF, GB, MLP:** Phase 3 설정, 시드 0 하나로 적합·예측 시간. 입력은 Phase 3에 저장한 Δz 파일이므로 Δz 계산 시간은 들어가지 않는다.
- **딥러닝 모델:** 새로 돌리지 않는다. v1.1 실행 기록(`addendum_v11/run_log.csv`: CruiseBench 180회, L4 GPU 분; `addendum_v11/addendum_v11/e2c_bayesrul_results/run_log.csv`: bayesrul, T4 GPU 분)을 그대로 요약한다.
- 런타임이 끊길 때를 대비해 서브셋별 측정값을 `m2_parts/`에 저장하고, 다시 실행하면 끝난 서브셋은 건너뛴다.

### 2.3 표현 규칙

- 기술적 비교만 한다. CPU와 GPU처럼 장비가 다른 값끼리 "몇 배 빠르다"고 쓰지 않고, 장비를 함께 적는다.
